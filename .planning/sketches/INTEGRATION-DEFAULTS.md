# Approved integration defaults

Status: Adopted 2026-08-19

Sketches 001–020 settle the dashboard's material visual and interaction decisions. The remaining questions are integration details that can be reviewed efficiently in the assembled application. They do not require additional standalone variants.

## Decision threshold

Use the strongest approved pattern by default when a choice affects only placement, responsive composition, focus return, token application, or the handoff between already-approved workflows. Record the choice here and review it in the integrated page.

Request a new user decision only when a choice materially changes product scope, feature ownership, persistence or data contracts, a major cross-mode workflow, or the dashboard's primary information architecture.

## Adopted defaults

### Structural consequences to temporal repair

After **Save Structure** succeeds, preserve the affected Page, scroll position, and logical focus. If the operation invalidated a saved Scene reference, expose a named **Scene needs repair** attention chip through the approved Context Shelf. Do not open Repair automatically and do not create a concurrent temporal draft. Activating the chip opens Time Content at that Scene's existing Repair flow; closing it returns to the preserved Build context.

### Shared Page row

Use one constant-height row with a flexible, horizontally contained Page scroller and pinned mode-owned actions. View pins **Chrono View** and **Compare charts**. Build keeps **Add Page** reachable and anchors the active Page's vertical action rail and Page Orbit to its tab. Mode changes retain Page selection and the dashboard start line. Phone exposes the approved View-only controls.

### Chart Details and source evidence

Open **Details** in a compact, non-dimming read-only right drawer; at phone width it becomes a full-screen sheet. It may show configured definition, citation, freshness, owner, and cadence only when those fields exist. **View source rows** opens the approved Dedicated Viewer Window. Closing either surface restores the invoking chart, Page, scroll position, and Focus or Comparison context.

### Chrono, Collection controls, and chart data states

Keep each approved owner unchanged: Collection navigation remains in the chart header, Loading/zero-row/Partial/Error remains in the plot-native State Plate, and Chrono remains in its viewport-owned controller. Add no integration chrome. Collection displays remain non-temporal and ineligible for Time Groups or Scenes. Eligible temporal charts follow the existing temporal safety and recovery contract.

### Later-surface theme coherence

Apply the approved three-style semantic roles and Light/Dark/System mappings to every later surface. Introduce no new palette, status meaning, or geometry. Status and focus remain understandable without colour. Exact token calibration is implementation work and is reviewed on the assembled page.

## Deferred rather than defaulted

- Named Audience composition presets remain deferred until ownership and persistence are specified.
- Quorum expansion, install-app promotion, new package/schema behavior, permissions, and other product-scope additions are not inferred from integration work.
- Decorative motion, exact component boundaries, and breakpoint tuning beyond the approved support boundary remain implementation details.

## Sketch-phase conclusion

No Sketch 021 is opened for these items. The next activity is integration of the approved winners into the real dashboard, followed by visual review of the assembled pages. A new sketch is justified only by a material product decision under the threshold above.
