# Author quick start

Draft for the engineering RC. Use the exact candidate and reviewed package listed in the rehearsal packet. Build is intended for a desktop-width workspace; phone acceptance covers View. See the [manual](app-manual.md) for detailed chart and source controls.

## Keep a recoverable copy

Open **Build → Scenario Passport → Download Dashboard Package** before changing content. Keep this original alongside its app version and checksum. Browser edits belong to this browser profile and origin until exported; copying a link does not copy your work. Save or discard each open draft deliberately before packaging.

To use a reviewed package, choose **Upload Dashboard Package**, inspect its change review, then confirm the intended replacement. Cancel if the sources, content, assets or temporal structure are unexpected. Cancellation or rejection should leave the existing dashboard intact; report any contrary behavior before continuing. If Audience is already open, reload or reopen it after a successful import and verify its charts before resuming.

## Prepare the exercise

1. In **Scenario Passport**, check identity, declared presentation resolution and exercise time. Save the Scenario draft. The fictional-data notice belongs on every output that may be photographed.
2. Use **Pages and sections** to arrange ordinary content. Save layout changes separately from chart changes. Review named consequences before moving or removing content.
3. Add or edit a chart through its authoring controls. Check source attribution, observation interpretation, units, missing values and matching policy. Preview its actual destination footprint. **Save Chart Changes** commits that chart; discarding returns to its saved state.
4. Inspect View at the intended room resolution and phone width. Dense charts must remain readable without changing the meaning of their data. Static content must be identified as static; an absent observation is not zero.

## Save a cross-page comparison

In **View**, choose **Compare charts** and select the intended charts across pages. Open **Compare**, choose the comparison layout and use **Save as Storyline**. This opens a Build draft; it does not immediately mutate saved content.

Name the Storyline, inspect its period and chart coverage, and check sparse observations. A chart's matching policy or explicit member override determines whether a selected date has a value. Keep no-observation states visible rather than silently substituting a value. Arrange View and Present layouts independently, then save. Discarding the draft must leave the original dashboard unchanged.

Reopen the saved item in View and Present. Its View band should leave ordinary page content available. Check source and observation time at a date with data and one without exact data. After saving chart bindings or source-data edits, reload or reopen Audience before checking the room output; time and matching updates do not replace the content already loaded there. The approved reference comparisons are listed in the [rehearsal packet](rehearsal.md).

## Review before sharing

Export the saved result and keep its app/package versions and integrity identity with your notes. Retain the previous export until the new package imports successfully into an isolated workspace. Local media must travel in a complete package; URL-hosted content remains a declared connectivity dependency.

Time controls, hidden charts and presentation selection do not restrict access to package bytes. Distribute only a reviewed phase or participant derivative whose sources and assets physically exclude unreleased information. Keep the full original and provenance companions with the operator. Use the existing factory for paired PDPC outputs; see the [maintainer guide](maintainer-release-and-rollback.md).
