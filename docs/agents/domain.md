# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root for domain vocabulary.
- `docs/adr/` for architecture decision records.

Before exploring an area, read the glossary and any relevant ADRs if they exist. If they do not exist, proceed without creating them upfront.

Use established glossary terms in issues, proposals, hypotheses and tests. Note meaningful vocabulary gaps for domain-modeling work. If a proposal conflicts with an existing ADR, identify the conflict explicitly.
